# Скрипты в `scripts/`

Каталог подключён в `~/.claude/scripts` через junction — деплой им не нужен,
правки видны сразу.

## `prune-allowlist.js` — чистка `permissions.allow`

Глобальный `~/.claude/settings.json` пухнет одноразовыми записями: каждое
«always allow» на уникальную команду добавляет точную строку (полный вызов
MSBuild или vstest с конкретными путями, `node` из temp-папки, `printf` с
конкретным текстом), которая больше никогда не совпадёт.

Скрипт удаляет только точные записи без хвостового `*` длиннее 120 символов;
обобщённые prefix-паттерны (`git status*`, `dotnet build *`) не трогает.
По умолчанию — сухой прогон, `--apply` пишет с бэкапом `.bak`,
`--ensure-readonly` добавляет базовые read-only PowerShell-паттерны, если их нет.
Обёртки рядом: `allowlist-preview.bat` (сухой прогон) и `allowlist-clean.bat`
(применение с подтверждением).

> ⚠️ **Только при закрытом Claude Code.** Живая сессия держит allow-список в
> памяти и переписывает `settings.json` из неё при каждом новом «always allow» —
> внешняя правка файла во время сессии затирается. Порядок: закрыть Claude Code
> → `node prune-allowlist.js --apply` → открыть заново.

Read-only PowerShell-командлеты (`Get-ChildItem`, `Get-Service`, `Get-Content`,
`Test-Path`, `Select-String`) не разрешаются автоматически, в отличие от
bash-овых `ls`/`cat`/`grep` — их стоит держать обобщёнными паттернами
(`PowerShell(Get-ChildItem*)`).

**Замер 2026-09-13: чистить нечем и незачем, решено оставить как есть.** Правило
скрипта (точные записи длиннее 120 символов) ловит одну запись из 269 — сухой
прогон даёт ноль. Настоящий мусор другой: из 178 точных записей 43 содержат
абсолютные пути, и по журналу команд (8.9 МБ, 21 615 строк) 24 из них не
встречаются ни разу, 15 — ровно один раз, 4 — дважды и более. Но правило «нет в
журнале → удалить» даёт два класса ложных срабатываний: команды хуков и строки
статуса в журнал не попадают вовсе (например нужная запись с `statusline.ps1`
показала ноль), а использование раньше начала ротированного журнала невидимо.
Выгода при этом нулевая: allow-список живёт на стороне харнесса и в контекст
модели не попадает, длина ему не мешает. Если тема вернётся — делать обратное:
заменить одноразовые записи обобщёнными шаблонами (`PowerShell(dotnet build *)`,
`Bash(git -C c:/Proj/X *)`), что уменьшает число будущих запросов на разрешение
ценой более широкой поверхности. И только при закрытом Claude Code.

## `session-cost.js` — стоимость сессий

Считает по транскриптам, включая `<сессия>/subagents/*.jsonl` и часовой кэш.
Запуск из папки проекта: `node ~/.claude/scripts/session-cost.js --since <дата>`.
Каждый замер — строкой в [costs.md](costs.md).

На модель печатается: цена по статьям (вход, запись 5m и 1h, чтение, выход),
доля чтения кэша во входе, доля думанья в выходе, всего токенов, средний и
максимальный контекст хода, `$/ход`, сколько ходов сделал водитель и сколько
сабагенты, запросы `web_search`/`web_fetch` (они платные сверх токенов и в
сумму не входят), `effort`, ветка и длительность сессии по `timestamp`.
Блок `ВСЕГО` даёт ту же однострочную сводку, что уходит в `costs.md`.

Блок «сабагенты по типам» — разрез сабагентов по `agentType` из
`agent-<id>.meta.json` (`Explore`, `general-purpose`, …): вызовов (файлов
транскрипта), запросов, входных токенов, входа и цены на вызов. Типы идут по
убыванию цены. Модель, которой нет в прайсе, дала бы $0.00 молча — она названа
в конце строки (`— без прайса: <модель>`), сумма считается по остальным. Нужен
для замера пункта 5.2 спеки «тонкий водитель»: цена типа агента, а не токены.

Флаг `--agents` добавляет блок «сабагенты по вызовам» — строку на каждый файл
транскрипта: описание из `description` в `meta.json`, тип, модель, `effort`,
вход и цена, по убыванию цены. Отвечает на вопрос «кто на какой модели и с
каким effort шёл»: в разрезе по типам агенты одного типа на разных моделях
сливаются в одну строку, а модель и effort в ней не печатаются вовсе.
Карта агентов в UI модель тоже не показывает. `effort` берётся из
`perTurnEffort` ходов сабагента: параметром он не задаётся, сабагент
наследует effort сессии, поэтому расхождение с водителем — повод проверить.

Обёртка рядом: `agents.bat` — из отдельного окна терминала, пока сессия идёт.
Без аргумента берёт проект текущей папки, с аргументом ищет папку проекта по
подстроке (`agents.bat Batch`), при промахе выходит с кодом 1. Только чтение,
живой сессии не мешает. Звать из самой рабочей сессии не стоит: вывод целиком
уходит в контекст, а ход стоит всего накопленного контекста.

Папка `%USERPROFILE%\.claude\scripts` добавлена в пользовательский `PATH`
(2026-09-16), поэтому обёртки зовутся по имени из любого места. Старое
значение переменной сохранено в `~/.claude/path-user.bak.txt`. В уже открытых
терминалах `PATH` старый — нужен новый терминал или полный путь.

Флаг `--prompts` добавляет блок «ходы владельца» — строку на каждое его
сообщение: время, запросов, из них сабагентских, вход, выход, доля кэша, цена
хода и начало текста. Ход владельца — окно от его сообщения до следующего:
привязка по `timestamp`, а не по цепочке `requestId`, поэтому в цену хода
попадает и то, что за это время потратили сабагенты. Отвечает на вопрос «во что
обошлось вот это моё „да“» — в замере 16.09 такой ход набрал 103M токенов за
786 запросов. Сообщения владельца отбираются тем же фильтром, что в чужом
`analyze-sessions.mjs`: без `isMeta`, `isCompactSummary`, `isSidechain`,
`tool_result`, уведомлений задач и прерываний. Ходы до первого сообщения
владельца не теряются — идут строкой со временем «—».

Строки `<synthetic>` — сообщения самого CLI (ошибка API, «No response
requested»), а не ходы модели: в статистику не попадают.

Запросы дедуплицируются по `requestId` в пределах файла: один ответ API пишется
в транскрипт несколькими строками, итоговый `output_tokens` несёт последняя.
Между файлами дублей нет — проверено 2026-09-16 на 173 транскриптах трёх
проектов, ноль пересечений, — поэтому суммы в `costs.md` не задвоены.

Тесты: `node --test scripts/*.test.js`.

## `handoff-from-transcript.js` — handoff по закрытой сессии

`/remember` пишет handoff только из живой сессии. Если её закрыли внезапно или
после долгой паузы (а по правилу паузы это верный шаг), остаются лишь
автозаписи плагина строками `today-*.md`. Скрипт достаёт handoff из транскрипта
задним числом.

Без аргументов — список пяти последних сессий проекта с пометкой:

```
#1  f85545fc-5521-4042-960d-2b079533d67a  2026-09-13 14:38—14:45    1 реплик  0.7 МБ  ✗ без /remember
#2  9e13bc7e-f7e6-4696-8f45-a101770b265e  2026-09-13 14:19—14:38    5 реплик  0.7 МБ  ✓ /remember 14:34
#5  f662092a-ef7a-4878-a291-c9626cab2929  2026-09-13 13:22—13:47   10 реплик  0.7 МБ  ⟳ /remember затёрт другой сессией
```

`✓` — handoff на месте, делать нечего. `✗` и `⟳` — звать сабагента на Haiku
(пометка `⟳` означает, что `/remember` был, но плагин держит один
`.remember/remember.md` на проект и более поздняя сессия его затёрла). Своим
handoff сессии считается файл, записанный между вызовом `/remember` и концом
сессии: скилл пишет его не мгновенно, а работа после него обычно продолжается.

С аргументом `<N|uuid|путь>` пишет выжимку в `%TEMP%\claude\handoff-<uuid8>.md`
и печатает только путь — его и передают сабагенту. В выжимку идут реплики
владельца, текст ассистента и вызовы инструментов одной строкой; вставки
скиллов и хуков (`isMeta`), вывод инструментов, размышления и ветки сабагентов
отброшены, хвостом — `git log` за окно сессии. Сессия 0.5 МБ даёт 9 КБ
(≈2.5k токенов): выжимка сабагентом ≈$0.02 против ≈$1.50 за возврат в старую
сессию ради handoff.

Ключ `--dir <папка>` берёт транскрипты другого проекта. Тесты:
`node --test scripts/handoff-from-transcript.test.js`.

## `transcripts.js` — где лежат транскрипты

Общий модуль для `session-cost.js` и `handoff-from-transcript.js`: папка
проекта в `~/.claude/projects` (имя резолвится через `readdir`, потому что
буква диска в имени встречается в обоих регистрах, а `existsSync` на Windows
этого не различает) и список сессий от старой к новой.

`projectDirs()` возвращает все каталоги проекта: слаг строится от cwd, поэтому
работа из подпапки заводит отдельный каталог и замер из корня видел только
свою часть. Каталог-кандидат подтверждается настоящим `cwd` из транскрипта —
слаг неоднозначен: `c--Proj-Foo-other` это и подпапка `Foo\other`, и соседний
проект `Foo-other`. Тесты:
`node --test scripts/transcripts.test.js`.

## `rename-session.js` — своё имя сессии в списке

Заголовок строки в панели собирается по приоритету `custom-title` → `ai-title`
→ первое сообщение. `ai-title` генерируется один раз по первому
содержательному промпту, поэтому сессии, начатые словом «дальше» из цикла
handoff'а, так и остаются «дальше», а сессия, ушедшая по ходу дела в другую
работу, носит имя первой темы.

Своё имя — одна строка `{"type":"custom-title","sessionId":…,"customTitle":…}`
в конце транскрипта; ровно так пишет команда расширения «Rename Session Tab».
Побеждает последняя запись, поэтому переименование повторяемо, а сайдкар
`custom-title.json` эта сборка только читает — писать в него бесполезно
(проверено). Панель перечитывает транскрипты не сразу: имя появляется после
перезагрузки окна.

    node scripts/rename-session.js --list
    node scripts/rename-session.js --session <id> --title "Суть работ"

Транскрипт, в который писали последние 30 минут, считается живым, и запись в
него запрещена — кроме своей сессии, чей id передан в `--self`. Так идущий
замер в соседнем проекте не сломать ошибочным вызовом. `--list` показывает
безымянные сессии (ни своего имени, ни сгенерированного), живые пропускает.
Тесты: `node --test scripts/rename-session.test.js`.

## `cache-split.js` — из чего складывается плата

`session-cost.js` говорит «сколько стоила сессия», этот — «куда ушли деньги»
по всем проектам сразу: доли записей в кэш (часовых и пятиминутных), чтений и
вывода плюс распределение TTL по моделям. Запуск: `node scripts/cache-split.js
2026-09-08` (дата — по времени изменения транскрипта; без аргумента — последняя
неделя от сегодня, посчитанная дата стоит первой строкой вывода).
Нужен для калибровки правил про кэш и паузы; замер 2026-09-13 —
в [costs.md](costs.md), раздел «Отдельные наблюдения».

## `cost-structure.js` — за что заплачено, а не сколько

`cache-split.js` делит плату на записи, чтения и вывод; этот идёт дальше и
раскладывает чтение кэша по размеру контекста хода, отдельно считая ходы
водителя и сабагентов. Разрез нужен потому, что рычаг лежит не в том, какой
скилл позвали, а в том, сколько контекста тащит каждый ход.

```
node scripts/cost-structure.js [--since 2026-09-15]   # доли, затем чтение по корзинам контекста
node scripts/cost-structure.js --ttl [--since …]      # что стоила бы запись при promptCacheTtl 5m
```

Режим `--ttl` честнее оценки из `cache-split.js`: он считает не только
дешёвую запись, но и перезаписи префикса после разрывов длиннее пяти минут —
разрыв меряется между соседними оплаченными ходами файла. Замер 2026-09-18
в [costs.md](costs.md): часовой TTL дешевле пятиминутного, менять нечего.

Тесты: `node --test scripts/cost-structure.test.js`.


## `prices.js` — прайс и коэффициенты записи кэша

Общий модуль для `session-cost.js` и `cache-split.js`: таблица цен ($/MTok),
нормализация имени модели (в транскриптах бывает с датой сборки) и
коэффициенты записи кэша — ×1.25 при TTL 5 минут, ×2 при часе. При смене цен
правится только этот файл. Прикрыт тестами `session-cost.test.js`.

## `context-composition.js` — из чего состоит контекст

`session-cost.js` отвечает, сколько заплачено; этот — за что. Запуск рядом с
замером пакета из папки проекта, для недельной картины — с `--global`:
`node ~/.claude/scripts/context-composition.js --global --since <дата>`.

Флаги те же, что у `session-cost.js` (`--all`, `--since`, явный путь), плюс
`--global` (все папки `~/.claude/projects`) и `--tail <символов>` — граница
«крупного» вызова, по умолчанию 8000.

Четыре блока:

- **Состав** — доля символов по частям: результаты инструментов, их входы,
  думанье, текст ассистента, реплики владельца и каждое вложение своей строкой
  (`attach:instructions` — CLAUDE.md, `attach:skill_listing` — перечень скиллов,
  `attach:hook_success` — вывод хуков). Видно, что из базового контекста под
  контролем владельца. Вложение меряется по впрыснутому тексту (`content`, у
  хука — `hookSpecificOutput.additionalContext` из `stdout`), а не по всему
  объекту: там текст хука лежит дважды и с экранированием переводов строк.
- **Инструменты** — объём результата, число вызовов, средний размер.
- **Хвост** — какая доля вызовов длиннее порога и сколько контекста они дают,
  с разбивкой команд `Bash` по виду (`cat`, `sed -n`, `grep`): так проверяется,
  обходят ли ворота `read-gate` и не режет ли потолок `bashOutputMaxChars`
  прогоны тестов.
- **Бюджет** — сессии и ходы по корзинам среднего контекста (до 100k,
  100–150k, от 150k) с долей чтений кэша, плюс базовый контекст — медиана
  первого хода. Сессии короче шести ходов не считаются: открыл и закрыл.

Считаются символы записанного транскрипта, а не токены, помноженные на число
ходов: цену части отсюда не получить, видно только, что растёт. Два вида
записей вынесены из долей и печатаются отдельно — служебные строки CLI
(`file-history-*`, `queue-operation`), которые в запрос не уходят вовсе, и
снимок системного промпта: он пишется при каждой смене, а платится один раз на
ход, и внутри долей размывал бы всё остальное. По той же причине доли не
совпадают с таблицей аудита `cost-audit-2026-09-14.md`, где знаменатель был
другой; порядок величин и все выводы сходятся.

Ходы сабагентов входят в состав и в хвост (их вывод набивает тот же контекст),
но в бюджет сессии — нет: у сабагента своя.

Тесты: `node --test scripts/context-composition.test.js`.

## `skill-usage.js` — кто из скиллов нужен и почём листинг

Дополнение к встроенному `/skill-doctor`, а не дубль: тот перечисляет только
плагинные и личные скиллы, встроенных в его таблице нет, и на соединении
Remote Control он отвечает «Skill usage reports are not available on this
connection» (отчёт при этом считается локально — проверка `ao(s.session)` стоит
после подсчёта). Данные те же — транскрипты `~/.claude/projects`.

```
node scripts/skill-usage.js [--since 2026-09-01]   # вызовы: сколько раз, когда, в скольких проектах
node scripts/skill-usage.js --listing              # цена листинга по скиллам, из папки проекта
node scripts/skill-usage.js --cost [--since 2026-09-01]  # деньги за работу скиллов и доля от суммы
```

Первый режим считает вызовы инструмента `Skill` по всем проектам сразу и
сортирует по убыванию — по нему видно, какие скиллы лежат в контексте зря.
Второй берёт свежий снимок листинга из последнего транскрипта текущего проекта
(значит, уже с действующими `skillOverrides`) и печатает длину описания каждого
скилла с итогом «плагины / встроенные». Плагинные отделены не для красоты:
`skillOverrides` на них не действует, они управляются только через `/plugin`.

Третий режим отвечает на вопрос, которого не брал ни один наш скрипт: во сколько
обходится работа скилла, а не его строка в листинге. Отрезок скилла — от вызова
`Skill` до следующего сообщения владельца; ход с самим вызовом в счёт не идёт
(решение позвать скилл принято до того, как его текст попал в контекст), второй
вызов в том же цикле забирает последующие ходы себе. Служебные записи типа
`user` — результат инструмента, впрыск хука, сводка сжатия, уведомление о
готовности сабагента — отрезок не закрывают. Ход, разбитый на несколько строк
с общим `requestId`, считается один раз.

Чего режим не видит: ходы сабагентов лежат отдельными файлами и в долю скилла
не попадают, поэтому скилл, работающий через сабагентов, показан дешевле, чем
стоит. Разрез по типам агента даёт `session-cost.js`.
Ошибка в другую сторону — незакрытый отрезок. Владелец в прогоне пакета молчит
часами, и всё, что шло после вызова скилла, приписывается ему: у
`superpowers:writing-plans` из $133.44 за 2026-09-15…18 написанием планов были
$78.09, остальные $55.39 — реализация после того, как план дописан
(`decisions/2026-09-18-subagent-templates-and-plan-cost.md`). Режим предупреждает
об этом строкой в выводе; число читать как «скилл и работа под ним», не как
цену самого скилла.

Замер 2026-09-14 в ClaudeOps: листинг 10 972 знака, из них 8 298 встроенные.

## `superpowers-hook-off.js` — снять впрыск плагина на старте

Плагин `superpowers` вешает SessionStart-хук, кладущий в контекст весь
`using-superpowers/SKILL.md`: 3 321 знак, ≈890 токенов на каждом ходу по парному
замеру ([decisions/2026-09-14-superpowers-hook.md](decisions/2026-09-14-superpowers-hook.md)).
Скрипт убирает блок `SessionStart` из `hooks.json` в кэше плагина, оставляя
рядом `hooks.json.bak`.

```
node ~/.claude/scripts/superpowers-hook-off.js            # снять впрыск
node ~/.claude/scripts/superpowers-hook-off.js --check    # вернулся ли он (код 1)
```

Правка вне репозитория и слетает при обновлении плагина, поэтому скрипт
идемпотентен (второй прогон файла не трогает, бэкап не затирает), путь ищет по
любой версии и маркетплейсу, а `hooks/session-memory.ps1` проверяет кэш на
каждом старте и подаёт строку с командой снятия, если впрыск вернулся.

## `analyze-sessions.mjs` — чужой анализатор, не из `scripts/`

Скилл `session-report@claude-plugins-official` (Anthropic) возит самостоятельный
скрипт, который читает те же транскрипты `~/.claude/projects`, что и наши.
Плагин для этого включать не нужно — файл лежит в зеркале маркетплейса, и
запуск по пути не стоит ни токена контекста:

```
node "$HOME/.claude/plugins/marketplaces/claude-plugins-official/plugins/session-report/skills/session-report/analyze-sessions.mjs" --since 24h --top 3
```

Флаги: `--since <ISO|7d|24h>` (без него — всё время), `--top N` (сколько
дорогих ходов печатать, по умолчанию 15), `--cache-break N` (порог разрыва
кэша, по умолчанию 100000 некэшированного входа), `--json`,
`--dir <папка проектов>`. Путь версии не содержит, обновление маркетплейса его
не ломает; проверено на Windows, 1041 файл за секунды.

Что даёт сверх наших скриптов: разрезы по скиллам и по типам сабагентов
(число вызовов и средние токены на вызов), разрывы кэша (вызовы с большим
некэшированным входом) и самые дорогие ходы с текстом промпта. Плюс два
времени: «активные часы» — время без пауз длиннее 5 минут, против часов по
стенным; в `--json` есть ещё разрез по дням `by_day` с раскладкой сессий по
времени суток, в текстовом выводе его нет. Денег не считает — только токены,
поэтому `session-cost.js` он не заменяет.

Штатное применение — замер пакета: `session-cost.js` даёт сумму в строку
[costs.md](costs.md), анализатор объясняет, из чего она сложилась (сабагенты,
доля кэша, конкретный дорогой ход).

## `session-report.js` — HTML-отчёт по транскриптам

Шаблон отчёта из того же скилла, заполняемый скриптом, а не моделью. Скилл
просит модель самой вставить JSON анализатора в шаблон и написать выводы; всё
это считается из цифр, поэтому отчёт не стоит ни одного токена:

```
node ~/.claude/scripts/session-report.js --since 7d -o report.html
```

Флаги: `-o <файл>` (по умолчанию `session-report.html` в текущей папке),
`--since` и `--dir` — проброс в анализатор. Готовый файл self-contained: данные
лежат в нём же, наружу он не ходит. Шаблон тянул JetBrains Mono из Google
Fonts — внешние `<link>` при сборке вырезаются, в CSS уже есть запасная
цепочка моноширинных.

Что делает: запускает `analyze-sessions.mjs --json`, кладёт JSON в
`<script id="report-data">` копии `template.html`, заполняет блоки
`AGENT: anomalies` (пять наблюдений: доля самого крупного проекта, доля кэша,
самый дорогой ход владельца, разрывы кэша, активное время) и
`AGENT: optimizations` (советы по порогам: кэш ниже 90 %, разрывы, сабагент
тяжелее 200k на вызов, больше 40 запросов на сообщение владельца). Не сработал
ни один порог — так и написано, совет не выдумывается.

Анализатор и шаблон берутся из зеркала маркетплейса перебором по установленным
маркетплейсам, в репозиторий не копируются: обновится плагин — обновится и
отчёт. Скилла нет — скрипт падает с именем недостающего файла.
