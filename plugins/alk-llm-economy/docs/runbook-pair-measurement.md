# Ранбук: пара пакетов L под замер (долги 6 и 11)

Для владельца, который ведёт замер руками. Один пакет = один заход = одна
сессия-водитель. Пакет A и пакет B идут подряд.

## Что меряется

| | Пакет A | Пакет B |
|---|---|---|
| Водитель | Opus 5 (1M), effort `high` | Fable 5.1, effort `high` |
| Исполнители | Sonnet 5 | Sonnet 5 |
| Схема цикла | L целиком, рецензент отдаёт одну строку вердикта | та же |
| Состав | 6 задач C#-половины долга Batch | 6 задач того же типового состава |

Различие ровно одно — модель водителя. Всё остальное держится одинаковым,
иначе пара не сравнивается ни с чем. Пилот долга 11 («водитель не платит за
каждый шаг цикла») едет внутри обоих пакетов одной и той же схемой ревью.

## До первой сессии, один раз

1. Правки промптов уже в дереве ClaudeOps (`d69b6d8`); `hooks/` и `docs/` —
   junction'ы, деплой им не нужен.
2. `permissions.deny` не трогать: `Workflow` остаётся запрещён. Его схема —
   +6 290 токенов в каждом ходу водителя, и они вошли бы в замер чужим
   расходом (`docs/decisions/2026-09-14-tool-schemas-deny.md`).
3. `autoCompactWindow` (сейчас 133000) и `env.CLAUDE_CODE_SUBAGENT_MODEL`
   (`sonnet`) не менять до конца пары.
4. Не обновлять Claude Code между A и B: одна версия CLI — условие сравнимости.
   Обновление всё же прилетело — записать версию в `docs/costs.md` и считать
   пару подпорченной, а не промолчать.
5. Выписать состав обоих пакетов заранее и убедиться, что каждый заход влезает
   в день: пакет идёт без пауз дольше часа.

## Состав: как делить

Берутся только C#-задачи из `docs/tech-debt.md` проекта Batch. Стендовые
(сайдкар, iptables, ядро, маскирование на живом стенде) в пакет не брать: там
цену хода задаёт стенд, а не модель.

Партии одного типового состава — по две тестовые задачи, по три правки кода,
одна конфигурационная.

**Пакет A**
1. `#` в поле `title` не доезжает до merge request (`TaskFileParser`).
2. `PumpAsync` заводит лишний linked CTS (`RunSession.cs:96`).
3. `StreamWriter` в `RunSession.cs:20` не освобождается явно.
4. Тест пиннинга git-конфига доказывает половину (`GitWorkspaceTests.cs:136-152`).
5. Флаки `GitWorkspaceTests.Publish_rejects_when_no_commits`.
6. Устаревшая запись `.gitmodules` без gitlink'а, с `update ≠ checkout`.

**Пакет B**
1. Флаки `FakeAgentTests.Timeout_kills_process_and_its_child` и
   `RunnerEndpointsTests.Aborting_request_kills_agent_process` — гонка без диагноза.
2. Флак `WaitForChildPid` (`RunnerEndpointsTests.cs:118-122`): читает файл сразу
   после `File.Exists`, лечится повтором чтения.
3. Ветки отказа разворота сабмодулей не покрыты тестами.
4. Сообщение об отказе при 67 и более сабмодулях: охрана обрезанного вывода
   (`GitWorkspace.cs:287-288`) стоит раньше предела ширины (`:346-347`).
5. `accept` зовётся под `_claimGate` — сериализует слоты.
6. `RunSession.MaskWorkTree` (`RunSession.cs:156`) зовёт `MaskTreeInPlace` со
   старым обработчиком.

Редакция от 2026-09-16, после пакета A: задачи 1 (`ReadCandidateAsync`) и 5
(тест ширины по gitlink'ам) старого списка закрыты самим пакетом A по правилу
замены, на их места встали находка водителя про текст отказа и флак
`WaitForChildPid`. Форма партии та же, что у A: три правки кода, две тестовые
задачи, один флак без диагноза.

Список водитель сверяет с актуальным `docs/tech-debt.md` на шаге спеки: задача
успела закрыться — берётся соседняя того же типа, число задач не меняется.

## Пакет A по шагам

1. Закрыть остальные сессии Claude. `/model` и `/effort` пишутся в общий
   `settings.json`, и чужая сессия посреди пакета собьёт замер.
2. Открыть Claude Code в `C:\Proj\Batch`. Дерево чистое, ветка `master`.
3. **До первого сообщения**: `/model` → Opus 5 (1M), `/effort high`. Проверить
   строку статуса.
4. Записать дату и время старта: дата пойдёт в `--since` при замере.
5. Отправить стартовый промпт целиком одним сообщением (ниже). Хук
   `model-notice` на первом промпте молчит, если модель дефолтная — для A
   молчание и есть подтверждение. Заговорил — модель не та, поправить до
   продолжения.
6. Дальше вмешиваться только там, где цикл просит решения владельца: приёмка
   спеки, приёмка плана, вопросы `AskUserQuestion`. Схему посреди пакета не
   менять — изменённая схема делает пакет несравнимым с B.
7. Пауз дольше часа не делать. Случилась — `pause-guard` заблокирует первый
   промпт и назовёт цену; заход считается разорванным, и это пишется в замер.
8. Конец — merge и замер (раздел «Финиш пакета»).

## Стартовый промпт

Копируется целиком, меняется только список задач и буква партии.

```
Уровень L. Пакет «мелкие находки, партия A» — он же контрольный замер водителя
(долг ClaudeOps 6) и пилот «водитель не платит за каждый шаг цикла» (долг 11).

Задачи — из docs/tech-debt.md, разделы «Публикация ветки воркером», «Git-конфиг»,
«Сабмодули», «Минорные находки из леджера», «Флаки-тесты на Windows»:
1. `#` в поле `title` не доезжает до merge request (TaskFileParser).
2. PumpAsync заводит лишний linked CTS (RunSession.cs:96).
3. StreamWriter в RunSession.cs:20 не освобождается явно.
4. Тест пиннинга git-конфига доказывает половину (GitWorkspaceTests.cs:136-152).
5. Флаки GitWorkspaceTests.Publish_rejects_when_no_commits.
6. Устаревшая запись .gitmodules без gitlink'а, с update ≠ checkout.
Сверь формулировки с файлом: закрывшуюся задачу замени соседней того же типа,
число задач не меняй.

Правила этого пакета, менять их посреди пакета нельзя:
- исполнители Sonnet 5; рецензент задачи смотрит дифф, финальный рецензент —
  полный набор ветки; рецензент всегда другой модели, чем автор;
- рецензент возвращает мне ОДНУ строку вердикта: PASS/FAIL, числа находок по
  серьёзности и путь к файлу отчёта. Находки я не открываю, маршрутизирую по
  числам, исполнитель получает путь (~/.claude/docs/agent-prompts.md);
- журнал SDD ведётся по ходу и служит источником истины: на каждую задачу —
  строка вердикта, число кругов исправлений и сколько находок рецензента
  подтвердилось на коде. После пакета восстановить это будет нечем, леджера
  в проекте больше нет;
- автосжатие включено и сработает примерно раз в час. После каждого сжатия
  первым делом перечитывай журнал SDD и `git log`, а не полагайся на память:
  сводка держит открытую нить и теряет закрытые.

Начни со спеки по циклу L.
```

## Автосжатие: чего не делать

- Срабатывает само около 99–100k (порог — `autoCompactWindow` минус постоянный
  буфер 33k), контекст после сжатия около 42k, один цикл покупает примерно час
  работы. Вмешиваться не нужно.
- Порог под замер не подгонять и ручной `/compact` не набирать — ни в A, ни в
  B. Режим сжатия обязан быть один в обоих пакетах.
- Хук контекстного бюджета на 100k почти не успеет спросить: автосжатие
  срабатывает раньше. Спросил — отвечать «продолжаем», не `/compact`.
- Слепую проверку сохранности сводки (долг 22) в пакет не втаскивать: она стоит
  ходов водителя и войдёт в сумму. Транскрипт никуда не денется — прогнать её
  после пакета из отдельной сессии по протоколу `docs/compaction.md`
  («Протокол чистого прогона»).
- Оговорка для `costs.md`: базовые $27.5 водителя (168 ходов, avg 142k, max
  231.6k) собраны без автосжатия и при старой схеме «строка на находку», так
  что сравнение A с этой базой меряет сразу две перемены. Чистой остаётся
  только пара A↔B, где режим один.

## Финиш пакета

1. `git merge --no-ff` в `master`, `git branch -d`.
2. `docs/results-<дата>.md` в Batch по шаблону из `templates/`.
3. Из папки Batch, одним ходом:

```
node ~/.claude/scripts/session-cost.js --since <дата старта пакета>
node "$HOME/.claude/plugins/marketplaces/claude-plugins-official/plugins/session-report/skills/session-report/analyze-sessions.mjs" --since <дата> --top 3
```

4. Строка в ClaudeOps `docs/costs.md` с полями долга 6: модель водителя, число
   запросов и `avg` по каждой модели, сумма, число задач, число кругов
   исправлений, число коммитов, сколько находок ревью оказались реальными.
   Плюс режим сжатия: `autoCompactWindow 133000`, сколько раз сработало
   автосжатие, был ли ручной `/compact` (в этой паре быть не должно).
5. `/remember`.

## Пакет B — отличия

1. Новая сессия сразу после A, тем же днём или следующим; между пакетами не
   обновлять CLI и не править правила в ClaudeOps.
2. До первого сообщения: `/model` → Fable 5.1, `/effort high`. Effort тот же,
   что в A: разный effort сравнивал бы две оси разом. Хук на первом промпте
   напечатает строку с ценой Fable — для B это и есть подтверждение, что
   модель встала.
3. Промпт тот же, состав — партия B.
4. После B вернуть дефолт: `/model` Opus 5, `/effort high` до первого сообщения
   следующей сессии.

## Как решается

Сравнивается цена задачи вместе с её ревью и кругами при равном числе кругов
исправлений. Дефолт меняется только при разнице больше 25 %; меньшее — шум двух
пакетов, а не преимущество модели.
