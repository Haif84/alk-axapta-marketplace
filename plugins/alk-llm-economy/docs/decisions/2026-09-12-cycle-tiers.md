# 2026-09-12 — цикл разработки: бюджет контекста, уровни задач, ревью сабагентом

## Контекст

Обсуждение 2026-09-12 «как оптимизировать цикл разработки». Цели по
приоритету владельца: стоимость пакета, церемония процесса, качество и
переделки. Скорость (время до коммита) вторична: не ухудшать, специально
не гнаться.

## Что известно

- Сессия Opus 5 `0534eeb9` (2026-09-12): 166 запросов, 28.8 млн токенов
  чтений кэша, 101k вывода, $19.52. Средний контекст на запрос — 173k.
- Базовый контекст сессии ≈ 40k токенов (первая запись в кэш сессии Fable
  `f254c0a7` — 40.5k), а не 85k, как записано в правилах. Инструкции в нём
  около 10k: глобальный CLAUDE.md 9.6k символов, проектный 2.5k, MEMORY.md
  2.4k, хендофф remember 3.7k. Остальное — системный промпт, схемы
  инструментов, описания скиллов плагинов.
- Следствие: три четверти платы — рост контекста от вывода инструментов,
  помноженный на число ходов. Плата за ход ≈ весь накопленный контекст.
  Половина длинной сессии дороже перезапуска (~$1 на Fable, меньше на Opus).
- Плагины `tgbot-agent` (14 скиллов), `alk-axapta-tools` (6 скиллов с
  абзацными описаниями), `alk-self-update` и MCP-сервер Axapta (60
  инструментов) включены глобально, то есть в каждой сессии каждого проекта.
  Реальные вызовы по транскриптам: MCP Axapta — Axapta, ALKTelBotLoy,
  Kashka2; скиллы tgbot-agent — бот-проекты; alk-axapta-tools — Axapta,
  Kashka2. Инструмент LSP не вызывался ни разу, но csharp-lsp даёт
  диагностику после правок пассивно — оставлен глобально.
- Пакет Batch: спека + план без реализации — $13.89. В правилах описан один
  цикл, полный; для мелких задач церемония дороже правки.
- Ревью другой моделью — отдельная сессия: ручной `/model`, повторный подъём
  базового контекста, повторное чтение спеки и кода, ручной перенос итога.
- Строка статуса получает `context_window.used_percentage` и
  `context_window.total_input_tokens` (документация statusline).

## Варианты

1. Только стоимость: бюджет контекста, правило ходов, плагины по проектам.
2. Только церемония: уровни задач, ревью сабагентом в той же сессии.
3. Оба, с контрольным замером уже на новом процессе (tech-debt 6).

## Выбор: вариант 3

Решение владельца 2026-09-12. Шесть правок:

1. **Бюджет контекста** вместо «одна задача = одна сессия»: строка статуса
   показывает контекст; при 50 % (100k) — `/remember` и новая сессия, даже
   посреди задачи.
   *Уточнение 2026-09-13:* порог задан в токенах (100k жёлтый, 150k
   красный), не в процентах. Окно у всех текущих моделей 1M, и 50 % окна —
   это 500k; строка статуса красила по проценту и за сессию в 187k так и не
   загорелась. Расчёт порога — `docs/costs.md`.
2. **Плагины по проектам.** `tgbot-agent`, `alk-axapta-tools`,
   `alk-self-update` глобально выключены, включены в
   `.claude/settings.local.json` проектов, где используются. MCP Axapta
   перенесён из user-scope в local-scope трёх проектов (`~/.claude.json`,
   `projects.<путь>.mcpServers`). Local, а не project: плагины из личных
   маркетплейсов, конфигурация MCP содержит заголовок авторизации.
3. **Правило ходов.** Независимые вызовы инструментов — одним ходом; после
   правки файл не перечитывать; вывод инструментов — сводки. Причина: цена
   хода равна всему контексту.
4. **Три уровня задач.** S — одно место в коде, ясная правка: TDD,
   verification, коммит, соло. M — одна цепочка на 2–5 файлов: дизайн в
   чате, соло, `/code-review` в конце. L — пакет из двух и более
   независимых кусков: полный цикл. Спека и план только для L.
5. **Ревью сабагентом другой модели** в той же сессии (Agent с `model`
   рецензента), на вход только спека/план и код. Правило «рецензент ≠
   автор» сохраняется; исчезают перезапуск и повторный подъём контекста.
6. **Доказательство в отчёте исполнителя.** Вывод команды тестов с кодом
   возврата; рецензент запускает тесты, а не читает диффы; `git add` только
   явных путей.
