# 2026-09-14 — потолок вывода Bash в контексте (`bashOutputMaxChars`)

## Решение

В машинном `settings.json` выставлено `"bashOutputMaxChars": 12000` вместо
дефолтных 30000. Вывод команды `Bash`/`PowerShell` длиннее 12k символов в
контекст не попадает: CLI сохраняет его целиком в файл
`projects/<проект>/<сессия>/tool-results/<id>.txt`, а модель получает путь и
первые 2 КБ. Нужное место читается из файла точечно — `grep -n` плюс
диапазонное чтение, как после отказа `read-gate`.

Кода нет: настройка встроена в CLI (2.1.269), диапазон допустимых значений
4000–128000, дефолт 30000. Проверена живьём в сессии 2026-09-14 — вывод
15.6 КБ ушёл в файл, тогда как при дефолте проходил инлайн; перезапуск сессии
для применения не нужен.

## Зачем

`read-gate` закрыл `Read`, но не обход через `cat`/`sed -n`. Замер
транскриптов за неделю (`docs/cost-audit-2026-09-14.md`) показал: 31 % хвоста
крупных вызовов `Bash` — это чтение файлов целиком, в основном у
исполнителей-сабагентов, где правило «через grep, в контекст только сводки»
держится на одной дисциплине модели.

Порог 12k символов — примерно 3k токенов, то есть цена одного такого чтения на
20-м ходу сессии равна двадцати оплатам этих 3k. Точное совпадение с порогом
`read-gate` (350 строк ≈ 28k символов) не требуется: `read-gate` отказывает и
заставляет выбрать способ чтения, а этот потолок ничего не запрещает — он
только не даёт длинному выводу осесть в контексте навсегда.

## Чем это отличается от хука

Хука на `Bash` с разбором командной строки не пишем: CLI режет вывод по факту
его размера, а не по догадке о том, что делает команда. Разбор `cat file` и
`sed -n 'a,bp'` промахивался бы и в одну сторону (`cat` маленького файла), и в
другую (`dotnet test`, `git log -p`, любой генератор длинного вывода).

## Что осталось открытым

Побочный эффект: длинный вывод тестов теперь тоже уезжает в файл. Правило
«исполнитель приводит в отчёте вывод команды тестов и код возврата» от этого не
меняется — код возврата виден всегда, а строки с падениями берутся из файла.
Если окажется, что 12k режет слишком рано на прогонах тестов, поднимать до
20000, а не возвращать дефолт.

Рядом есть `taskOutputMaxChars` — тот же потолок для фоновых задач. Не трогаем
до замера: фоновые задачи в наших сессиях редки.
