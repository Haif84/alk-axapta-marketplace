# 2026-09-16 — разбор статьи «Тюнинг Cursor»: что берём, что нет

## Источник

https://habr.com/ru/articles/1029868/ — vpomo (Владимир Помогалов), «Тюнинг
Cursor: как я укротил AI-ассистента и радикально снизил счета за токены с
помощью MCP-серверов». Три MCP-сервера (`rag-code-mcp`, `lean-ctx`,
`mcp-on-demand`) плюс набор конфигов Cursor с лимитами токенов; заявлена
экономия «до 90 % бюджета токенов».

## Решение

Ни один инструмент автора не берём. Из его практик в долг взяты три пункта:
23, 24, 25 в `docs/tech-debt.md`. Разбор записан, чтобы не пересматривать
статью второй раз.

## Что автор говорит верно, но у нас уже сделано

| Утверждение | Где у нас |
|---|---|
| `Cache Read` дешевле `Input` в 10 раз; смотреть надо на `Input` и `Cache Write`, а не на общий объём | замер собственных сессий дал ~13× ($0.04 против $0.82); разрез по всем проектам делает `scripts/cache-split.js` |
| Жёсткий лимит токенов на запрос и на сессию, аварийная остановка при превышении | `hooks/context-budget.ps1`, порог 100k с блокировкой на 150k (`decisions/2026-09-15-compact-at-threshold.md`). У автора это строчка в `AGENTS.md`, то есть надежда, а не исполнение |
| Описания инструментов MCP съедают 30–50 % контекста, их надо прятать за мета-инструментом | в Claude Code встроено: deferred tools + `ToolSearch`. Схемы неиспользуемых инструментов сняты отдельно, −20 928 токенов на ходу (`decisions/2026-09-14-tool-schemas-deny.md`) |
| Конфиги без инструмента не работают: модель сама нужный путь не выберет | тот же вывод стоит в шапке `hooks/read-gate.ps1`: правило — это надежда, держит только то, что нельзя обойти рассуждением |

Совпадение четырёх независимых выводов — единственная содержательная ценность
статьи для нас.

## Что отвергнуто

- **`rag-code-mcp`** (Ollama + Qdrant, AST-эмбеддинги, 16 ГБ RAM, ~8 ГБ
  моделей). Окупается на чужой большой монорепе, где разведка идёт наугад. У
  нас свои небольшие репозитории, где `grep -n` плюс Explore на Haiku дешевле
  и не требует переиндексации.
- **`lean-ctx`** — сторонний бинарь, который ставит глобальный shell-hook и
  проксирует чтения и команды. Против базиса безопасности: неаудированный
  посредник на всём выводе. Его функции у нас закрыты `read-gate`, потолком
  `bashOutputMaxChars` 12k (`decisions/2026-09-14-bash-output-cap.md`) и
  `test-output-filter`.
- **Правило «остановиться, если `Cache Read` больше 10 % контекста»**
  противоречит разделу самой статьи, где большой `Cache Read` назван
  признаком эффективности, и её же итоговому замеру с 727k `Cache Read` как
  хорошим результатом. Копировать нечего.
- **Цифра «до 90 %»** — без базы сравнения и методики, по одному запросу.
  По нашим правилам (`docs/costs.md`) это не замер.
