# 2026-09-13 — автономия агента: ветка и запись стоимости

## Контекст

Владелец: агенты по ходу работ спрашивают про ветку («в какой работать»,
«вливать ли») и спрашивают разрешение на запись строки стоимости в другой
репозиторий. Пример из сессии: «Стоимость прогона: $36.36 … В
ClaudeOps/docs/costs.md не внесена — сказать туда строку?». Оба вопроса
задаются каждый раз, ответ каждый раз один и тот же.

## Почему спрашивали

- Ветка: в правилах был только шаг 4 цикла «`merge --no-ff` в основную
  ветку», без слов «не спрашивать» и без судьбы ветки после вливания. Скилл
  `superpowers:finishing-a-development-branch` по своей инструкции предлагает
  владельцу варианты интеграции — то есть спрашивает.
- Стоимость: базовое правило автономии запрещает «writes outside the repo»
  без согласия, а `docs/costs.md` лежит в другом репозитории. Правило про
  замер не было названо исключением, поэтому агент честно останавливался.

## Решение

1. Ветка описана в разделе «Коммиты» глобальных инструкций: L — своя ветка от
   основной (та, на которой HEAD в начале сессии), S и M — прямо в основной;
   вопросов про ветку не задаёт ни водитель, ни сабагент. После приёмки —
   локальный `git merge --no-ff` (вливание видно в истории отдельным
   коммитом) и `git branch -d`; ветка без своих коммитов удаляется сразу.
   `git push` по-прежнему только по явному слову.
2. Запись стоимости в `ClaudeOps/docs/costs.md` объявлена заранее
   разрешённой — из любого проекта, без вопроса; в разделе Autonomy добавлена
   оговорка про названные исключения.

## Почему запись стоимости общая, а не на уровне проекта

Файл `costs.md` — единственный корпус калибровки правил выбора модели. Если
запись оставить на усмотрение проекта, её нужно прописать в CLAUDE.md каждого
проекта и она будет пропадать в новых; корпус станет выборкой из тех
проектов, где не забыли, и калибровка по нему перестанет что-либо значить.
Место записи одно и известно, риск записи нулевой (добавление строки в
git-репозиторий), поэтому дешевле разрешить один раз глобально.
